# 오늘의 진짜 정보판 — 원/달러 환율 (과제 4)

매일 바뀌는 USD/KRW 환율 한 값을 기록하고, 그 값이 언제·어디서 왔는지 함께 보여주는 정보판입니다.

## 공개 심사 주소

- 결과물: https://terran1234.github.io/daily-board-04/
- 소스: https://github.com/terran1234/daily-board-04

로그인·계정·비밀키 없이 열립니다.

## 카드 1 — 값이 뜻하는 바

| 항목 | 내용 |
|---|---|
| 값 | 달러(USD) 1개를 사는 데 필요한 원화(KRW) |
| 단위 | KRW per 1 USD |
| 출처 | ExchangeRate-API 공개 엔드포인트 `https://open.er-api.com/v6/latest/USD` (키 없음) |
| 출처 시각 | 응답의 `time_last_update_unix` — 출처가 값을 갱신한 때 |
| 조회 시각 | 이 화면(또는 기록 스크립트)이 값을 받아온 때 |
| 기준 시간대 | KST (Asia/Seoul, UTC+9) |

출처 시각과 조회 시각은 다른 시각입니다. 출처는 하루 한 번쯤 갱신하고, 화면은 열 때마다 조회합니다.

## 정상 한 건의 원자료 · 저장값 · 화면값 대조

2026-09-30 KST에 받은 정상 응답 한 건입니다. 세 값은 같습니다.

| 단계 | 어디에 있나 | 값 | 시각 |
|---|---|---|---|
| 1. 원자료 (받은 그대로) | [`data/raw/2026-09-30.json`](data/raw/2026-09-30.json) 의 `rates.KRW` | `1353.681844` | `time_last_update_unix` = `1790726551` → 2026-09-30 09:02:31 KST |
| 2. 저장값 | [`data/latest.json`](data/latest.json) 의 `value` | `1353.681844` | `source_time_kst` = `2026-09-30T09:02:31+09:00`, `fetched_at_kst` = `2026-09-30T16:06:33+09:00` |
| 3. 화면값 | 결과물 화면 "정상 한 건 대조" | `1,353.68` | 출처 시각 2026-09-30 09:02:31 KST |

- 원자료 − 저장값 = 0
- 화면값 규칙: 저장값(전체 자릿수)을 소수 둘째 자리까지 반올림해 표시합니다.
- 화면은 이 저장 기록을 실제로 읽어 와 세 값이 같은지 스스로 확인하고, 다르면 "일치하지 않습니다"를 띄웁니다.

## 카드 2 — 비밀 없는 호출

**결과: 브라우저 코드·배포 파일·네트워크 응답·Git 기록 네 곳에서 비밀키 원문 0건.**

이유는 단순합니다. 출처(`open.er-api.com`)가 키 없이 쓰는 공개 엔드포인트라서, 브라우저는 인증 헤더·토큰·쿼리 키 없이 평범한 GET 하나만 보냅니다. 숨길 값이 처음부터 없습니다.

| 어디를 검색했나 | 대상 | 비밀값 |
|---|---|---|
| 브라우저 코드 | 저장소 파일 6개 (`index.html` 포함) | 0건 |
| 배포 파일 | 공개 주소에서 받은 파일 6개 | 0건 |
| 네트워크 응답 | 공개 주소를 연 브라우저의 요청 6건(출처 API, 저장 기록 2개, 폰트 2개, 페이지) 요청 주소·응답 본문 | 0건 |
| Git 기록 | 커밋 7개의 diff와 커밋 메시지, 브랜치 `main` 하나 | 0건 |

네트워크 세부:

- 출처 API 요청 주소는 `https://open.er-api.com/v6/latest/USD` 뿐이고 쿼리 값이 없습니다.
- 코드에는 `Authorization` 같은 사용자 지정 헤더를 붙이는 부분이 없습니다.
- 쿠키·`localStorage`·`sessionStorage`에 저장된 값이 0개입니다.
- 쿼리 값이 있는 요청은 폰트 CSS의 `family`, `display` 둘뿐이며 글꼴 이름입니다.

### 다시 확인하는 법

```
powershell -File scan.ps1
powershell -File scan.ps1 -BaseUrl https://terran1234.github.io/daily-board-04
```

검색 스크립트는 GitHub·AWS·Google·Slack 토큰 형태, 개인 키 블록, Bearer 토큰, `Authorization` 헤더, 키 이름에 값을 대입하는 문장, 주소 뒤에 키·토큰 이름의 쿼리 값이 붙은 경우를 찾습니다. 찾은 곳의 파일·줄·종류만 출력하고 값 자체는 출력하지 않습니다.

검색기 자체가 제대로 동작하는지도 확인했습니다. 합성 시험값(가짜 토큰, 가짜 키 대입문, 가짜 개인 키 머리줄 등 7건)을 심어 7건이 모두 잡히는 것을 본 뒤 삭제했습니다.

한계: 패턴 검색이라 알려진 형태만 찾습니다. 그래서 "키가 없는 출처를 쓴다"는 설계가 실제 방어선입니다.

### 만약 키가 필요한 출처로 바꾼다면

1. 브라우저에서 부르지 않고 서버 쪽 경로(서버리스 함수 등)로 옮깁니다.
2. 이미 노출된 키가 있으면 즉시 폐기합니다.
3. 새 키는 서버 환경변수에만 저장하고, 코드와 저장소에는 남기지 않습니다.

## 파일 구성

```
index.html              정보판 화면 (실시간 조회 + 저장 기록 대조)
scripts/record.ps1      정상 응답 한 건을 원자료 그대로 + 저장값으로 남기는 스크립트
scan.ps1                저장소·배포 파일의 비밀값 검색 스크립트
data/raw/YYYY-MM-DD.json  받은 그대로의 원자료 (KST 날짜별)
data/latest.json          저장값 (값, 단위, 출처, 두 시각, 시간대)
```

`record.ps1`은 응답이 `success`가 아니거나 KRW 값이 없으면 아무것도 저장하지 않습니다.
